# TaskFlow — To-Do List

A simple and modern To-Do List application built with **Node.js, HTML5, CSS3, and Vanilla JavaScript**.

This project was developed as a learning and portfolio project to explore backend development, RESTful APIs, HTTP communication, and frontend integration without relying on external frameworks or dependencies.

## Features

- **Create tasks:** Add new tasks with a title.
- **List tasks:** Retrieve and display all existing tasks.
- **Complete tasks:** Toggle tasks between completed and pending states.
- **Delete tasks:** Remove tasks from the list.
- **Real-time interface updates:** Refresh the task list after user interactions.
- **Responsive design:** Use the application on desktop and mobile devices.
- **Input validation:** Reject empty task titles and titles exceeding 200 characters.
- **In-memory storage:** Manage tasks using a JavaScript array on the server.
- **Built-in HTTP server:** Serve static frontend files and handle API requests using native Node.js modules.

## Technologies

### Backend
- [Node.js](https://nodejs.org/)
- Native Node.js modules:
  - `http` — HTTP server and request handling.
  - `fs` — Static file access.
  - `path` — File path management.
  - `crypto` — Unique task identifiers using `randomUUID()`.

### Frontend
- HTML5
- CSS3
- Vanilla JavaScript
- Fetch API

**No external packages, backend frameworks, or frontend frameworks are required.**

## Getting Started

### Prerequisites

Install Node.js on your machine.

You can download it from the official website:

https://nodejs.org/

Verify your installation by running:

```bash
node --version
```

**1. Clone the repository**

```bash
git clone https://github.com/CesarNahra/todo-list.git
```

**2. Navigate to the project directory**

```bash
cd todo-list
```

**3. Start the server**

```bash
node server.js
```

You should see the following message:

```text

```

**4. Open the application**

Visit the following address in your browser:

http://localhost:3000

The application is now ready to use.

No package installation or build process is required.

## REST API

The application exposes a REST API for managing tasks.

### Task Object

Each task follows this structure:

```json
{
  "id": "unique-task-identifier",
  "titulo": "Study Node.js",
  "concluida": false
}
```

| Property | Type | Description |
|---|---|---|
| `id` | String | Unique identifier generated by the server. |
| `titulo` | String | Task title. |
| `concluida` | Boolean | Indicates whether the task has been completed. |

### Endpoints

| Method | Endpoint | Description | Success Status |
|---|---|---|---|
| `GET` | `/api/tarefas` | Retrieve all tasks. | `200 OK` |
| `POST` | `/api/tarefas` | Create a new task. | `201 Created` |
| `PATCH` | `/api/tarefas/:id` | Toggle a task's completion status. | `200 OK` |
| `DELETE` | `/api/tarefas/:id` | Delete a task. | `200 OK` |

### 1. Retrieve All Tasks

**Request**

```http
GET /api/tarefas
```

**Response**

```json
[
  {
    "id": "unique-task-identifier",
    "titulo": "Study Node.js",
    "concluida": false
  }
]
```

If no tasks exist, the API returns an empty array.

### 2. Create a Task

**Request**

```http
POST /api/tarefas
Content-Type: application/json
```

**Request Body**

```json
{
  "titulo": "Learn REST APIs"
}
```

**Response**

The server generates a unique identifier and initializes the task as incomplete.

```json
{
  "id": "generated-task-identifier",
  "titulo": "Learn REST APIs",
  "concluida": false
}
```

The response status is `201 Created`.

### 3. Toggle Task Completion

**Request**

```http
PATCH /api/tarefas/unique-task-identifier
```

The endpoint toggles the task's `concluida` property between `true` and `false`.

No request body is required.

**Response**

```json
{
  "id": "unique-task-identifier",
  "titulo": "Learn REST APIs",
  "concluida": true
}
```

The response status is `200 OK`.

### 4. Delete a Task

**Request**

```http
DELETE /api/tarefas/unique-task-identifier
```

**Response**

```json
{
  "mensagem": "Tarefa excluída com sucesso.",
  "tarefa": {
    "id": "unique-task-identifier",
    "titulo": "Learn REST APIs",
    "concluida": false
  }
}
```

The response status is `200 OK`.

### Error Handling

The API uses standard HTTP status codes to indicate the result of a request.

| Status Code | Description |
|---|---|
| `200 OK` | The request was successful. |
| `201 Created` | A new task was created successfully. |
| `400 Bad Request` | The request contains invalid data. |
| `403 Forbidden` | Access to a restricted file path or file type was denied. |
| `404 Not Found` | The requested route, resource, or file was not found. |
| `405 Method Not Allowed` | The HTTP method is not supported for the requested resource. |
| `413 Payload Too Large` | The request body exceeds the configured size limit. |
| `500 Internal Server Error` | An unexpected server-side error occurred. |

## How It Works

TaskFlow follows a simple client-server architecture.

1. The browser loads the HTML, CSS, and JavaScript files served by Node.js.
2. The frontend uses the Fetch API to communicate with the backend.
3. The server processes incoming HTTP requests and performs the requested operations.
4. Tasks are stored in an in-memory JavaScript array.
5. The frontend updates the DOM to reflect the current task list.

The backend and frontend share the same origin, so no additional CORS configuration is required.

## Data Storage

Tasks are stored in memory using a JavaScript array:

```javascript
let tarefas = [];
```

This approach keeps the project simple and avoids the need for a database during the initial development stage.

**Important:** Tasks are not persisted between server restarts. All stored tasks are lost when the Node.js process stops.

A future version could introduce persistent storage using a JSON file, SQLite, or another database.

## Current Limitations

This project is intended for learning purposes and is not designed for production use.

Current limitations include:

- No persistent database.
- No user authentication or authorization.
- No task editing functionality.
- No task categories, priorities, or due dates.
- No automated test suite.
- No rate limiting or advanced request security controls.
